# 学生工作台与登录稳定性组合态收口审计交接

## 目标、范围与前置

本合同只收口两项已完成批次的**最终组合态**：学生工作台五项后续修复，以及复旦登录耗时与稳定性最小修复。目标是确认它们在同一工作树中可以安全合并、给出必要的最小修复和提交拆分建议；不是重新实施功能、重跑真实业务，或把离线证据表述为真实服务修复。

先完整阅读根 `AGENTS.md`、`docs/handoff.md`、`docs/student-workspace-followup-handoff.md`、`docs/fudan-login-stability-execution-handoff.md`。本文件与它们冲突时，按更严格的边界执行。仅 `private/main` 可编辑；`public/worker-mirror` 为生成镜像，`managed/personal-worker` 与 `managed/mailbox` 为托管状态，均不得手改。

先做 fresh preflight：在 `private/main` 执行 `git status --short`，记录目标文件 diff/hash、当前调用链、测试入口和离线性。**所有**现有脏改动、未跟踪文件和测试数量均属用户基线，除本合同明确新增的文件外不得覆盖、删除、`reset`、`stash`、`restore`、`checkout`，也不得将 patch 快照、临时仓库、缓存产物或自动生成副本当作证据来源或提交对象。若其他写任务仍在运行或树持续漂移，停在只读审计，待其终态后重做 preflight。

禁止读写 `runtime/data`、`public`、`managed`，禁止真实认证、真实课表刷新、真实任务/取消、Git add/commit/push/PR/release、Secrets 操作和任何外部写入。不得输出凭据、cookie、ticket、URL query、账号、课程正文或遥测原始敏感字段。本合同不接收或继承任何真实验证授权；即使用户随后给出 GO，也必须另开任务、另写交接并重新通过风险门禁，本合同仍只允许离线与合成验证。

## 调度与交付纪律

阶段 A 只读；阶段 B 仅在阶段 A 找到可复现、明确归因的 P1/P2 时进行。使用单一 worker 顺序工作，禁止并行写入；凭据、认证、会话、票据、遥测保留或其他信任边界相关改动前，先由 `risk_auditor` 做只读 gate 并取得 PASS。完成后由独立 `reviewer` 审阅当前增量，结论只能是 `ACCEPT`、`ACCEPT_WITH_FOLLOWUPS` 或 `REJECT`。不要扩展功能、重构或改变已获接受的协议、DPAPI、账户隔离、凭据格式、2FA、`operation_id`、任务系统或 Worker 协议。

先用证据决定精确 allowlist；每一项写入必须能指向 P1/P2 根因和对应离线回归。无根因、需超范围路径、需协议/发布或 gate 未通过时停止并报告，而不是猜测性修复。

## 阶段 A：最终组合态只读审计

建立简短决策记录，列出检查的最终工作树、两批次的实际文件交集、证据、风险、是否需要阶段 B。至少完成以下检查。

### 1. `src/application.py` 重叠语义

追踪两个批次在 `src/application.py` 的完整调用链与全部调用者，特别是字幕入队能力自适应、DeepSeek key 保存语义、登录遥测/认证准备状态及它们共用的状态、错误与响应字段。确认不存在后写覆盖先写、错误闭集错映射、`saved`/`configured` 误用、无 key 时错误依赖、或导致登录状态被 catalog/字幕状态污染。只审计最终源码，不比对 patch 快照来推断语义。

### 2. 最终离线测试基线

报告中的 `696` 与 `700 passed` 不作为结论。确认测试命令没有真实外联、真实凭据或运行时数据依赖后，以 fresh 的最终组合态全量 client/worker suite 的实际计数为唯一基准；若环境或已有失败阻断，记录完整命令、失败归因和 `unavailable`，不得选择旧计数。区分本增量失败、用户基线失败与环境不可用。

### 3. DeepSeek 三态与字幕自适应

以合成 fixture 或既有离线测试验证以下矩阵，不读写真实凭据：

| DeepSeek key | 任务时点 | 必须确认 |
| --- | --- | --- |
| 有 | 新建任务 | 唯一 `automatic` 策略（2026-09-14 取代旧模式兼容）：AI 校对路径。 |
| 无 | 新建任务 | `automatic` 自动走非 AI 回退，任务与界面诚实标记“无大模型校对（自动降级）”，不把它显示为失败；摘要/问答硬依赖不被降级。 |
| 有后删除 | 已排队任务 | 明确任务入队时究竟快照了何种 mode/config；若随后删除 key 会造成标准任务空 key 运行，记录为既有边缘并判定其风险，只有明确 P1/P2 根因且 gate 通过才最小修复。 |

同时确认 `remember=false` 仅表示本次启动使用，不会静默删除已有本机保存 key；显式移除才删除。不得测试或打印 key 值。

### 4. 登录票链探针跳过

按最终代码和离线合成测试检查“成功票链后跳过双确认探针”的精确前提、分支与回退。必须确认：恢复路径仍有验证；过期票据不会被当作成功；错误重定向不会被掩盖；预检探针仍保留；失败仍遵守既有 deadline、退避和不重复登录约束。不得访问真实 IdP/WebVPN 或用真实登录验证这些分支。

### 5. 遥测隐私与保留

审查 `LoginStageTelemetry` 的 schema、写入位置、调用路径和测试。确认仅允许阶段名、时间或 `duration_ms`、闭集 outcome/error、必要安全 HTTP status、attempt 和 operation_id 的短 SHA-256 投影；不得记录 URL、query、header、cookie、ticket、账号、密码、课程或请求/响应正文。确认文件有可执行且有界的保留机制；如果当前没有，应判为 P2 并在风险 gate 后以最小机制处理，不引入新服务或依赖。

### 6. 课表结论边界

检查课表前端是否把 load/refresh 失败、`partial_failures` 和下一步诚实呈现，并仍与课程目录恢复面板分离。只使用合成 fixture/离线 harness 验证**错误呈现**，不得把该项表述成真实课表源、SSO 或上游可用性已经修复。真实课表刷新无条件超出本合同范围；如确有必要，停止并建议另开任务、另写交接和重新通过风险门禁。

## 阶段 B：有证据时的最小修复

仅处理阶段 A 确认的 P1/P2。每个修复前记录根因、精确路径、为何是最小解及离线回归；若涉及凭据、认证、票据、遥测或保留，先 `risk_auditor` PASS。单 worker 按依赖顺序落地，保留用户脏基线，不改无关文件。

优先删除死分支或复用已有测试/保留模式；不得新增依赖、后台服务、定时任务、协议字段或新 UI 功能。若“排队后删除 key”的既有边缘无法在不改变 Worker/协议或派发语义的情况下安全解决，将其保留为 follow-up，不以伪修复掩盖。

## 验证、合成验收与停止条件

先确认每一命令离线或使用合成 fixture。按变更范围执行 `node --check`、相关 mjs harness、定向 client/worker pytest 和 fresh 最终全量 client/worker suite；报告命令与实际计数。涉及 UI 时，必要时运行既有合成浏览器 harness，覆盖课表错误呈现、无 key 字幕标签、任务抽屉、保存状态和单一搜索，并验证 1440/1000/375 亮暗无用户可见横向溢出。不得为截图开启真实登录或读取课程内容。

停止并报告：没有 P1/P2；工作树漂移；需要任何真实认证、课表刷新或任务操作；risk gate 非 PASS；需要 runtime/data、public/managed、协议发布或超 allowlist；或离线性无法确认。真实操作只能另开任务和交接，后续 GO 也不得在本合同内解除该停止条件。

## 最终报告与不执行的提交建议

最终报告应包含：

1. fresh preflight 与脏基线保护情况；
2. 阶段 A 六项逐项结论、证据和真实验证状态；
3. 阶段 B 文件、根因、最小性和 risk gate（若有）；
4. 离线/合成验证命令、实际计数、失败归因；
5. reviewer 结论及 P0/P1/P2；
6. 未验证项、停止原因和完整 `git status --short`；
7. 建议的提交拆分顺序与每个建议提交的文件边界，**只建议，不执行 Git 写操作**。
