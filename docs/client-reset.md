# 客户端重置（设置危险区）

最后更新：2026-09-16（冻结合同 `product-reset-feature-contract-20260916.md`）

客户端重置把应用恢复到全新安装状态：课程目录、任务、课表、搜索索引、观看进度、书签、测验、复习计划、本地分析与本机保存的凭据全部清除，随后应用自动关闭（**不自动重启**），需要手动重新打开并重新登录。

## 操作入口

设置 →「重置」分组 →「重置应用…」。弹窗中：

- 需要输入「重置」二字，确认按钮才会启用（与后端二次校验一致，精确匹配、不去空白）；
- 「同时删除课程派生产物（字幕 / AI 产物 / 课件）」默认**不勾选**；
- 「同时删除 GitHub 专属仓库」默认**不勾选**。

## 重置范围

**始终清除（基础重置）：**

- 两个本地数据库（`state.db`：目录/任务/自动化/远程台账；`learning.db`：字幕缓存/文档/搜索/测验/复习/统计）以原路径重建为全新空库（逐表清空后重跑既有建表路径）；
- `documents/`（本地上传的学习资料副本）、`migration-backups/`、更新暂存区 `updates/`（含受管安装的 `state/pending.json`）；
- 本机凭据：全部已保存复旦账号、全部会话检查点、DeepSeek Key、全部 GitHub 记录（令牌、安装 id、Worker 密钥对、专属仓库记录等）。凭据只经既有删除 API 清除，任何密钥值都不会被读取或展示；
- GitHub 默认语义 = 本机撤销令牌并清除全部客户端记录；不做服务端会话吊销声明。

**仅勾选「删除派生产物」时：** 字幕缓存（`artifacts/subtitles/` 与 `transcript_*` 行）、AI 产物（`ai_artifacts` 三表）、课件缓存（`courseware/` 与 `ppt_pages` 行）一并删除。不勾选时这三组**保留**，目录恢复后按原 `course:sub` 键自动重新挂载；学期轮换后它们会以孤儿形式出现在数据管理页，可在那里管理。

**仅勾选「删除 GitHub 专属仓库」时：** 对凭据中记录的两个客户端创建的专属仓库（Worker 仓库与 Mailbox 仓库）各执行一次整仓删除。这是闭集操作：绝不按名称模式或属主枚举仓库；分发仓库 `gualtier-xu/Fudan-CourseLens-Worker-Release` 永远不在闭集内。**权限类拒绝**（应用令牌任何层级都没有删仓权限，属架构性限制）不再整体中止：被拒仓库记入手删回执（受信 `github.com/{owner}/{repo}/settings` 链接），本地重置照常完成，学生点击链接进入仓库 Settings 页手动删除，删除后重新登录并执行一次诊断即可确认仓库已消失。**瞬态失败**（网络断开 / 限流 / 超时）仍整体失败，**本地不做任何改动**，可待 GitHub 恢复后重试。

## 安全门

以下任一情况存在时重置被整体拒绝（返回 409 `reset_blocked`，零执行）：进行中的任务、可恢复的远程 run、等待导入的自动化结果、未释放的远程令牌租约、待完成的安全清理（cleanup-pending）、自动化课程规则。同一时刻只允许一次重置（单飞）。

输入的确认语不是「重置」时返回 400 `reset_confirm_required`。

## 回执（后台摘要，非备份）

执行前会自动在**数据根之外**生成一份 `summary.v1` 脱敏数据摘要（含孤儿条目，≤200 行）：

- 受管安装：`<install_root>/reset-receipts/reset-<UTC>.json`；
- 源码形态：`runtime/reports/reset-receipts/reset-<UTC>.json`。

最多保留最近 5 份，写入新回执时自动删除更旧的。回执仅供诊断对账，**不是备份，不能用于恢复**，界面上也不提供下载入口。

成功回执（action result）包含删除计数、释放字节、（如勾选）已删除仓库名单，以及（如发生权限类拒绝）`repos_manual_deletion` 手删记录：每条含仓库全名、受信 Settings 链接与闭集原因 `app_token_cannot_delete`。界面对手删记录只渲染序号化链接，不回显仓库名单。

## 幂等

`client-reset:<operation_id>` 台账只记录已接受的回执；被阻塞或失败的尝试不计入，同一 operation_id 可在解除阻塞后重试。已接受的回执写入重建后的全新数据库，重放同一请求不会再次执行重置。

## 已知边界

- 重置不触碰分发仓库、GitHub 服务端的 Actions/Issue 历史、系统凭据存储的其他内容；
- `updates/update.lock` 在进程存活期间被占用，可能留存至进程退出后由下次启动回收；
- 学期轮换后保留的派生产物以孤儿形态呈现在数据管理页，属预期行为。
