# 学生面文案政策（Copy Policy）

> 一页纸规则，防新文案散落复发。来源：D14 无障碍审计 backlog P3-1（2026-10-07；
> 外部化判据沿同报告 §4「i18n 现状」）。本产品为单语（zh-CN）、无 i18n 框架——
> 本政策只立纪律，不启动外部化。

## 唯一去处：闭集表与具名常量

学生看得见的新文案（错误提示、状态说明、空态、确认话术、指引）优先进既有闭集
「码→文案」表，或模块顶部具名常量；禁止散落在交互逻辑的模板串里。

| 文案族 | 唯一落点 |
|---|---|
| 错误/瞬态提示（码→人话） | `frontend/modules/api.js` `ERROR_MESSAGES`（登录/目录/传输/深度回答/通用兜底） |
| 任务死因 | `frontend/modules/tasks-drawer.js` `TASK_FAILURE_GUIDANCE` |
| 证据/状态说明 | `frontend/modules/ui.js` `EVIDENCE_DETAILS` / `STATE_DETAILS` |
| 连接状态文案族 | `frontend/modules/ui.js` `CONNECTION_*` |
| 复习面审查态 | `frontend/modules/course-review.js` |

## 三条规则

1. **新码新文案进表**：新增错误码/状态码时，人话文案与码同处闭集表；同一码多处
   出现必须逐字同话，防措辞漂移（既有先例：`api.js` 的 `cloud_setup_required` 与
   `TASK_FAILURE_GUIDANCE` 逐字一致）。
2. **学生可见面零英文句式**：只写 zh-CN；品牌词（CourseLens/DeepSeek/GitHub/
   Worker/WebVPN/PDF/ICS/AI）与键帽（`Ctrl K`）为合理保留。D14 审计实测全站英文
   句子残留为 0，新文案不得打破。
3. **讲人话**：文案遵产品北极星的人情味要求——错误提示像一位耐心的同学在解释，
   不像系统日志；安全与权限类提示用「最小权限+具名清单」框架，禁技术性责备措辞。

## i18n 边界（现在不做）

i18n 真实需求出现前**不做全量外部化**：不引入 locale 切换器与字符串表加载器，
静态 HTML 不动。判据（D14 §4）：单语产品、复旦学生画像近中期无双语需求、三张
闭集表已是现成换肤种子。若未来真实需求出现，既定骨架分三步——①闭集表迁
`frontend/locales/zh-CN.js`（纯常量搬家，行为零变化）→ ②模块面 `t(code)` 包装器
渐进替换 → ③静态 HTML 最后动（量最大、收益最低）。

## 新代码检查单

- 要显示一条学生看得见的错误/状态？先查闭集表有无现成码；没有就加码进表，
  不在页面代码里写裸模板串。
- 要复用既有文案？逐字复制，禁止顺手改写（同一事实只有一种说法）。
- 想做 i18n/多语言？先停——按上节判据，真实需求出现前只维护闭集表纪律。
